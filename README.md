PROJECT
Create a modern, professional, highly visual 13-slide presentation website that behaves like a real PowerPoint presentation, built as a single-page web app with slide navigation.

Presentation Title: FROM IDEA TO DEPLOYED AI PRODUCT — BUILD · REPRODUCE · DEPLOY
Subtitle: How AI, research, and the cloud can turn a college project into a real-world product.

AUDIENCE
Final-year diploma students preparing for industry, internships, final-year projects, technology careers, software development, AI/ML careers. Beginner to intermediate technical level. Explain concepts in very simple language, avoid unnecessary jargon, and whenever a technical concept is introduced, explain it visually and simply.

PRESENTATION GOAL
Students should leave understanding this journey: PROBLEM → AI-ASSISTED DEVELOPMENT → RESEARCH → PROTOTYPE → CLOUD DEPLOYMENT → REAL PRODUCT → PORTFOLIO.
Core message: A college project becomes much more valuable when you understand the technology, reproduce useful research ideas, deploy the application, and demonstrate it as a real product.

VISUAL DESIGN
Premium modern technology presentation. Color palette: Primary Dark Navy Blue, Secondary White, Accent Light Blue, Highlight Orange (used sparingly for important actions, highlights, arrows, buttons, key messages).

VISUAL STYLE
Use modern AI visuals, cloud architecture diagrams, developer illustrations, research paper visuals, AI brain/neural network visuals, AWS/cloud visuals, code editor visuals, API/database diagrams, cards, timelines, flow diagrams, icons, progress indicators, large typography, minimal text, strong whitespace. Should look like a professional technology conference presentation. Must NOT look like a school PPT, generic template, documentation website, wall of bullet points, or boring corporate presentation.

ANIMATION PRINCIPLES
Animations must be meaningful: fade, slide, scale, sequential reveal, morph-like transitions, moving arrows, progressive diagrams, highlighting, flow animations. Do not overuse. Use animation to explain the story — e.g. build architecture diagrams one component at a time rather than all at once.

PRESENTATION NAVIGATION
Implement Next/Previous buttons, slide counter (e.g. "1 / 13"), progress bar, keyboard arrow navigation, spacebar → next, fullscreen mode, presentation mode where controls become subtle during presentation.

RESPONSIVE PRESENTATION DESIGN
Must work well on desktop, projector, large screen. Prioritize 16:9 presentation dimensions. Text must remain readable from a distance — avoid tiny fonts.

=== SLIDE-BY-SLIDE CONTENT ===

SLIDE 1 — TITLE
Headline: FROM IDEA TO DEPLOYED AI PRODUCT
Subtitle: How AI, research, and the cloud can turn a college project into a real-world product.
Large secondary text: BUILD · REPRODUCE · DEPLOY
Include "Presented by:" with space for two presenter names.
Visual: a modern technology journey row: 💡 Idea → 🤖 AI → 📄 Research → 💻 Build → ☁️ Cloud → 🚀 Product, with a subtle rocket/technology journey visual. Animation: journey builds left to right.

SLIDE 2 — THE QUESTION WE START WITH
Title: YOU HAVE AN APP IDEA. WHAT HAPPENS NEXT?
Large central question: "You have an app idea today. How do you turn it into something people can actually use?"
Four large visual cards appearing one at a time:
01 — BUILD IT 🤖 "AI Across the Development Lifecycle" — AI can assist with Requirements, Coding, Testing, Debugging, Deployment.
02 — REPRODUCE IT 📄 "Why Research Papers Matter" — Don't just consume AI. Understand how AI ideas actually work.
03 — DEPLOY IT ☁️ "Take It to the Cloud" — Move from: My Laptop → Real Users.
04 — YOUR TURN 🎯 "Interactive Challenges" — Students will design their own AI-powered application.
Bottom: BUILD → REPRODUCE → DEPLOY

SLIDE 3 — TRADITIONAL VS AI-ASSISTED SOFTWARE DEVELOPMENT
Title: SAME LIFECYCLE. NEW TEAMMATE.
Subtitle: AI does not remove the software development lifecycle. It changes how efficiently we move through each stage.
Four large horizontal comparison rows (not a dense table), Traditional appears first then AI-Assisted slides in:
REQUIREMENTS — Traditional: You list features alone. AI-Assisted: AI helps identify missing requirements and edge cases.
CODING — Traditional: You write every line manually. AI-Assisted: AI helps draft code — you review and own it.
TESTING — Traditional: You manually think of test cases. AI-Assisted: AI suggests cases you may have missed.
DEPLOYMENT — Traditional: Create configurations from scratch. AI-Assisted: AI explains and assists with CI/CD and configuration.
Bottom highlighted statement: AI IS A TEAMMATE — NOT A REPLACEMENT FOR UNDERSTANDING.

SLIDE 4 — WHERE AI CAN HELP
Title: WHERE AI CAN RIDE ALONG
Large horizontal lifecycle: 💡 IDEA → 📝 DESIGN → 👨‍💻 CODE → 🧪 TEST → 🐛 DEBUG → 🚀 DEPLOY → 📊 MONITOR
Tiny AI capability per stage: IDEA - Generate requirements; DESIGN - Suggest architecture; CODE - Generate/explain code; TEST - Create test cases; DEBUG - Explain errors; DEPLOY - Assist CI/CD; MONITOR - Analyze logs.
Use an AI icon animating/moving through the lifecycle.
Bottom: SAME DEVELOPMENT STAGES. AI SIMPLY HELPS YOU MOVE FASTER.
Prominent warning: ⚠️ Never deploy or submit AI-generated code you do not understand.

SLIDE 5 — INTERACTIVE CHALLENGE
Title: 60-SECOND CHALLENGE
Scenario: Your college wants an application where students can report campus problems.
Example visual cards: 💡 Broken lights, 💧 Water leaks, 📶 Wi-Fi issues, 🏫 Classroom problems.
QUESTION 1: Who are the users?
QUESTION 2: What is ONE important feature this application needs?
Encourage students to shout answers. Include an engaging visual 60-second countdown timer. Do NOT reveal the answer. Should feel interactive (a working on-screen timer that presenters can start).

SLIDE 6 — HUMAN + AI
Title: NOT AI VS DEVELOPER. AI + DEVELOPER.
Two large side-by-side cards:
👨‍💻 DEVELOPER/HUMAN — Understands: the real problem, users, business requirements, important decisions, risks. Owns: validation, quality, security, final outcome.
🤖 AI — Helps: generate ideas, suggest solutions, write and explain code, generate tests, debug, automate repetitive work.
Center: HUMAN + AI, then 🚀 FASTER + BETTER DEVELOPMENT.
Main message: AI may make coding faster, but understanding the problem still requires a human.
Animation: developer and AI cards move toward center, then reveal "AI + Human = Modern Development".

SLIDE 7 — WHY REPRODUCE RESEARCH PAPERS?
Title: EVERYONE CAN USE AI. FEW CAN REBUILD WHAT POWERS IT.
Three large visual cards:
01 — REAL SKILL, Not Surface Skill — Reading and implementing a research paper helps students understand how AI systems actually work. Visual: Research paper → Algorithm → Code → Result.
02 — STAND OUT, Differentiate Yourself — Compare "I used ChatGPT." vs "I implemented an idea from a research paper." (highlight the second).
03 — START SMALL, You Don't Need to Rebuild Everything — Choose one idea → Build a small prototype → Understand the result.
Bottom: READ → IMPLEMENT → UNDERSTAND → IMPROVE

SLIDE 8 — RESEARCH → WORKING APPLICATION
Title: FROM A RESEARCH IDEA TO A WORKING APP
Three-stage visual pipeline with progressive animation:
01 — THE CONCEPT: Retrieval-Augmented Generation. Show: 📄 Your Documents → 🔎 Retrieval → 🤖 AI → 💬 Answer. Simple explanation: RAG allows AI to answer questions using your own documents instead of relying only on its training data.
02 — THE PROTOTYPE: PDF Chat Application. Flow: User uploads PDF → System processes document → User asks question → AI retrieves relevant information → AI gives grounded answer.
03 — THE REAL APPLICATION: Deploy It. Show: Prototype → Cloud → AI Services → Real Users.
Main message: A RESEARCH CONCEPT CAN BECOME A REAL PORTFOLIO PROJECT.

SLIDE 9 — TAKING THE APPLICATION TO THE CLOUD
Title: FROM YOUR LAPTOP TO THE WORLD
Clean AWS-style architecture flow: 👤 USER → 🌐 API GATEWAY → ⚙️ AWS LAMBDA → 🤖 AMAZON BEDROCK → 🗄️ S3 STORAGE. Also show optional EC2. Use arrows and simple explanations: API Gateway receives the request; Lambda runs the business logic; Amazon Bedrock provides access to AI models; S3 stores documents/files/output; EC2 can run application servers when needed.
Show concept: LAPTOP → CLOUD → REAL USERS.
Message: A project running only on your laptop is a prototype. A deployed project becomes something people can actually use.
Small label: AWS = Cloud Platform. Keep explanations beginner-friendly.

SLIDE 10 — GROUP ACTIVITY
Title: BUILD YOUR APP IN 5 MINUTES
Subtitle: Work in pairs.
Four large visual boxes: 01 WHO? — Who is the user? / 02 AI? — Where can AI help? / 03 DATA? — What data or database is required? / 04 CLOUD? — How would you deploy it?
Bottom: SHARE — Ask 2–3 groups to explain their idea.
Visual: 👥 Pair → 💡 Idea → 🤖 AI → ☁️ Cloud. Make this slide energetic and interactive.

SLIDE 11 — FINAL YEAR PROJECT ROADMAP
Title: YOUR FINAL-YEAR PROJECT, REIMAGINED
Start with OLD APPROACH: Idea → Code → Demo → Submit, shown crossed out visually.
Then reveal INDUSTRY-STYLE APPROACH as a large roadmap: 💡 IDEA → 🤖 AI-ASSISTED REQUIREMENTS → 🏗️ ARCHITECTURE → 💻 BUILD → 🧪 TEST → 🚀 DEPLOY → 🎤 DEMO.
Supporting concepts around the roadmap: GitHub, Documentation, Testing, Cloud, AI, Research.
Main statement: Don't just build a project and submit it. Then: UNDERSTAND IT. TEST IT. DEPLOY IT. SHOW IT.
Final message: That is what turns a college submission into a portfolio project.

SLIDE 12 — THREE THINGS TO REMEMBER
Title: 3 THINGS TO REMEMBER
Three huge numbered cards appearing sequentially:
01 AI CHANGES HOW, NOT WHAT — The software development lifecycle remains the same. AI helps us move through it faster.
02 REPRODUCE, DON'T JUST CONSUME — Don't only use AI tools. Try implementing ideas from research papers. Understand how they work.
03 THE CLOUD MAKES IT REAL — A deployed application is more valuable for your portfolio than a project that exists only on your laptop.

Minimal, memorable closing slide. Large heading: QUESTIONS? Subtitle: Thank you. Then: BUILD · REPRODUCE · DEPLOY. Small message: Now go build, reproduce, and deploy something amazing.
